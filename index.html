A complete, offline-first design system for Android Automotive OS infotainment. Purple-themed, built on Material 3 and the Android for Cars design guidance, and shaped around one rule above all others: the driver's eyes belong on the road.

Principles

Design principles

Automotive UI is a secondary task. These principles override aesthetic preference whenever they conflict.

Glanceable

Key information is readable in under two seconds. One primary action per screen, large type, strong contrast, no dense paragraphs.

Safe by default

Every flow has a driving and a parked variant. Anything needing sustained attention, reading or typing is locked while the vehicle moves.

Shallow & predictable

No more than three levels deep. Back is always in the same place. Same control, same behavior, everywhere.

Multimodal

Every task is reachable by touch, rotary/hardware keys and voice. No gesture-only or hover-only affordances.

Large & forgiving

76 dp targets, generous spacing, and no precision gestures — the car is moving and hands are reaching, not resting.

Android-native

Material 3 shape, color roles and motion, adapted for distance viewing; consistent with Android Auto and Car UI Library behavior.

Automotive color rules

  • Night first. Backgrounds ≤ #141218 luminance; avoid pure white text blocks (glare) — onSurface is tinted #E6E0E9.
  • No pure #000 panels on OLED except surfaceContainerLowest system bars; keep subtle tone shifts for depth.
  • Red is reserved for safety-relevant faults and destructive actions; don't use it for decoration. Keep telltale colors consistent with ISO 2575.
  • Auto day/night follows ambient light / headlamp state via UiModeManager; transition with a 300 ms cross-fade, never a hard flash.
  • Contrast: text ≥ 4.5:1, large text & icons ≥ 3:1 (WCAG 2.2 AA); aim for ≥ 7:1 on driving-critical text. See the contrast checker.

Foundations

Typography

Roboto (system default on AAOS; OEMs may supply a brand face via RRO). Scale is enlarged ~1.5–2× over phone defaults for 60–80 cm viewing distance.

Minimums

24 sp for anything the driver must read while moving. 20 sp only for tertiary, non-critical meta (e.g. timestamps). Never below 20 sp.

Physical check

ISO 15008 targets ≈ 16–20 arcmin character height. At 750 mm that is ≈ 3.5–4.4 mm — verify on the real panel, since dp ≠ mm across displays.

Weights

Regular (400) for reading, Medium (500) for actions and labels. Avoid Light and Thin — they break up on automotive panels and in sunlight.

Writing for glance

Titles ≤ 25 characters, body ≤ 120 characters, sentence case, one idea per line. Truncate with ellipsis; never shrink text to fit.

Layout & spacing

All dimensions snap to an 8 dp grid (4 dp for icon/text alignment). Touch geometry is the hard constraint; visual density follows from it.

Spacing scale

Touch & hit targets

Visual size vs hit area
76 dp hit area
≥ 16 dp gap
  • Minimum target 76 × 76 dp; primary driving actions 96 dp. Visual element may be smaller, hit area may not.
  • Minimum 16 dp between adjacent targets (8 dp absolute floor for dense toggle groups).
  • Place frequent controls in reach zone: toward the driver's side and lower half of the display.
  • No tiny close icons, drag handles, edge swipes or multi-finger gestures.

Foundations

Iconography

Material Symbols (Rounded, weight 400–500, fill for selected). Inline SVG here so everything works offline. Click an icon to copy its name.

Sizes

32 dp inline/status, 40 dp default, 48 dp dock & FAB, 96 dp+ hero. Optical padding included; hit area is always ≥ 76.

Meaning

Pair every critical icon with a text label. Don't reuse standard icons (home, phone, hazard) for other meanings; use ISO 2575 telltale symbols for vehicle functions.

Selected state

Outlined → filled, plus pill indicator. Never rely on color shift only.

Focus & interaction states

Rotary controllers and steering-wheel keys depend on a clearly visible focus indicator. Touch users must also see focus when the input mode changes.

Focus ring

6 dp, tertiary, 4 dp offset, rounded to the component shape. Contrast ≥ 3:1 vs. adjacent surfaces.

Focus order

Reading order (leading→trailing, top→bottom) with nudge shortcuts to jump between toolbar, content and dock.

Default focus

Restore last focus on return. On first entry focus the primary action or first list item, never a destructive button.

Interaction

Input modalities

ModalityUseRules
TouchPrimary on most displaysTap only. Avoid long-press, double-tap, drag-to-reveal and edge swipes. Scroll via inertia list or paging buttons. Feedback < 100 ms.
Rotary / D-padRequired in many marketsRotate = move focus, nudge = jump zone, press = activate, back = hardware back. Every interactive element is focusable; no focus traps.
Steering-wheel keysMedia, voice, callMap to KEYCODE_MEDIA_*, KEYCODE_VOICE_ASSIST, KEYCODE_CALL/ENDCALL. Never remap.
VoicePreferred while drivingGoogle Assistant App Actions / Car App Library intents. Every touch task has a voice equivalent; confirm destructive actions aloud.
Physical buttonsVolume, HVAC, hazardOn-screen counterpart mirrors hardware state; hazard is never replaced by touch.

Feedback

Visual

State layer within 100 ms; focus ring on rotary; progress for anything > 1 s.

Audio

Short earcons for confirm / error / lane-change; respect per-stream volumes (USAGE_ASSISTANCE_*, USAGE_MEDIA), duck on prompts.

Haptic

Where hardware supports it, a crisp tick on press for touch panels used while driving.

Error handling

  • Say what happened and the next step: "No connection. Showing saved maps." — not codes.
  • Recoverable errors are inline banners; blocking errors use a dialog with 1–2 actions.
  • While driving, defer non-urgent errors until parked.

Checklist

Perceivable
  • Text ≥ 4.5:1; UI & icons ≥ 3:1; focus ring ≥ 3:1.
  • Never color alone — add icon, text or shape. Test with protan/deutan/tritan simulation.
  • Support font scale up to 130% and display size changes.
  • Captions/transcripts for any parked video.
Operable
  • All functions via touch, rotary and voice.
  • Targets ≥ 76 dp; no path-based or timed gestures.
  • No time limits < 10 s on essential decisions; allow extend.
  • No content flashing > 3×/s.
Understandable
  • Plain language, sentence case, consistent terms.
  • Labels visible, not placeholder-only.
  • Predictable navigation; Back always works.
  • Errors state cause and fix.
Robust (Android)
  • contentDescription on every icon-only control.
  • Correct roles: switch, checkbox, tab, heading.
  • Announce state changes via announceForAccessibility/live regions.
  • Test with TalkBack, Switch Access, Voice Access.
Safety-critical alertsMust never rely on color only, never be dismissed by timeout, must be announced audibly, and must remain at ≥ 7:1 contrast in both Day and Night.
Accessibility

Content, voice & localization

Do"Navigate home" · "18 min" · "Call Alex" · sentence case, numerals, locale units (km/mi, °C/°F), 12/24 h per region.
Don't"Please be advised that your route has been recalculated" · ALL CAPS sentences · jargon ("ECU fault 0x4F").
  • Tone: calm, brief, human. Address the driver directly; never blame.
  • Length: titles ≤ 25, labels ≤ 20, body ≤ 120 characters.
  • Localization: externalize strings, use ICU plurals, allow +40% expansion, support RTL mirroring (icons with direction mirror; media transport does not), and locale-aware numerals.
  • Voice prompts: ≤ 10 words, confirm before irreversible actions, offer a spoken escape ("Cancel").
